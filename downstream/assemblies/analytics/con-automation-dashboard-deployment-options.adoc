= Automation dashboard deployment options

[role="_abstract"]
Choose how to deploy automation dashboard: integrated with {PlatformNameShort} 2.7 (containerized or operator), or as a standalone utility on RHEL for measuring savings across multiple deployments (2.4 and later).


== Keywords

* automation dashboard
* automation savings
* integrated automation dashboard
* standalone automation dashboard utility
* deployment options

*Product:* {PlatformName} 2.7

== Overview

Automation dashboard calculates the time and cost savings your automation delivers so you can report on and improve the return on your automation investment. You can deploy it in two ways, depending on how you run {PlatformNameShort} and how you want to manage the dashboard over its lifecycle.

Both options present the same savings metrics and visualizations. The difference is the deployment model and how many deployments you measure, not the data you see.

== Integrated automation dashboard

The integrated automation dashboard is deployed as part of an {PlatformNameShort} 2.7 installation and is managed within the platform, under the *Analytics* section. You enable and configure it during installation using one of the following deployment methods:

* Containerized installation on RHEL
* Operator-based installation on Red Hat OpenShift

Because it is part of the platform, the integrated dashboard is upgraded and maintained alongside your {PlatformNameShort} deployment, and it collects data from that deployment automatically.

== Standalone automation dashboard utility (RHEL only)

The standalone automation dashboard utility is installed and managed separately from the {PlatformNameShort} installer, and is supported on RHEL only. It has its own lifecycle, including installation, configuration, data synchronization, cluster access token verification, and uninstallation.

Use the standalone utility when you want to connect to multiple {PlatformNameShort} instances, including deployments on different {PlatformNameShort} versions (2.4 and later), and aggregate their savings data in a single dashboard.

NOTE: The standalone utility cannot filter the dashboard UI by source {PlatformNameShort} instance.

== Running both together

You can run the integrated dashboard and one or more standalone utilities at the same time. The {PlatformNameShort} 2.7 UI provides the integrated dashboard for that deployment, and you can also deploy the standalone utility to connect to one or more {PlatformNameShort} versions.

== Analytics API availability by deployment type

Metrics service exposes an analytics API that allows authorized external tools to retrieve raw, non-anonymized automation data for BI integration. Analytics API access requires metrics service to be present in your deployment. Availability varies by deployment type:

* *Managed cloud (Red Hat-hosted):* Metrics service is pre-installed. No additional deployment steps are required for analytics API access.
* *Containerized RHEL (on-premise):* Metrics service requires explicit deployment. You must add the `[automationmetrics]` inventory group during installation to enable analytics API access.
* *Operator on OpenShift (on-premise):* Metrics service requires explicit enablement. Set `metrics.disabled: false` in the AnsibleAutomationPlatform custom resource to enable analytics API access.

For full analytics API prerequisites, including hardware, database, and system requirements for each topology, see xref:ref-metrics-service-deployment-requirements[Metrics service deployment requirements].

== Comparison

=== Integrated vs. standalone automation dashboard

[options="header"]
|===
|Consideration |Integrated automation dashboard |Standalone utility (RHEL only)
|Where it is deployed |Part of the platform installation |Installed separately on RHEL
|Supported install methods |Containerized (RHEL) or Operator (OpenShift) |RHEL only
|Lifecycle management |Upgraded and maintained with the platform |Installed, configured, upgraded, and uninstalled independently
|Data source |The {PlatformNameShort} deployment it is installed with |One or more clusters or {PlatformNameShort} deployments, connected using cluster access tokens
|{PlatformNameShort} version availability |{PlatformNameShort} 2.7 onwards |Utility can connect to {PlatformNameShort} versions 2.4 onwards
|Analytics API access |Available when metrics service is deployed (managed cloud: pre-installed; on-premise: requires explicit deployment or enablement) |Not applicable; standalone utility does not include metrics service
|===

== When to use each option

=== Use the integrated automation dashboard when:

* You are installing, or already running, {PlatformNameShort} 2.7 or later with the containerized or operator-based installer.
* You want the dashboard deployed, upgraded, and maintained as part of the platform.
* Your automation savings data comes from a single {PlatformNameShort} deployment.

=== Use the standalone automation dashboard utility (RHEL only) when:

* You run on RHEL and cannot or do not want to enable the dashboard during a platform installation.
* You want to connect to and aggregate savings from multiple {PlatformNameShort} deployments (2.4 and later).
* You want to manage the dashboard on its own lifecycle, separate from the platform.
